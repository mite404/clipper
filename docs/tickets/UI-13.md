# UI-13

Authoritative state: [master ticket](../master-tickets.md#ui-13).

## User story

As an editor, I want a dense, continuous audio waveform so I can see speech, pauses and transients
at any timeline zoom and cut on them.

## Evidence and scope

The [research owner](https://ampcode.com/threads/T-a7ae6f1e-63eb-400b-80a3-702a2ebd3335) inspected
the owner's reference and the bundled demo on `cd9500d`. In `src/media.ts`, `readMedia` samples
every 32nd audio sample into one absolute peak per frame across channels. `Waveform` in
`src/components.tsx` stretches exactly 120 SVG bars over any clip width. These independent limits
lose brief transients and turn zoomed audio into broad blocks.

The owner confirmed one combined stereo waveform, not separate L/R lanes. The reference calls for a
centered min/max envelope with a brighter inner RMS core. The waveform uses a fixed audio rate in
bins per second, independent of video FPS and well above it. CLIP-15 owns audible scrubbing, not
waveform detail. Delivered REF-14 corrected the FPS bin rate, not these decode and rendering limits.
Existing sample-to-time conversion already uses the actual buffer sample rate; a 44.1 kHz versus 48
kHz mismatch is not today's demonstrated cause.

The owner narrowed the method to BBC audiowaveform-style data aggregation implemented in our own
existing Mediabunny import loop, without a new dependency or a second decode. This supersedes the
earlier proposed mixed-rate fixture and reference-comparison acceptance pipeline.

## Acceptance

1. Read every sample in the existing import loop and mix channels into one combined waveform. Store
   min/max and RMS at a fixed audio bins-per-second rate independent of `FPS`, placing samples with
   each buffer's actual `sampleRate`. The waveform must not read the meter's frame-rate `peaks`;
   those may remain for the meter without changing its meaning.
2. Render one column per device pixel of the visible clip span, with an outer min/max envelope and a
   brighter RMS core. Bound rendering to the visible area or tiles without exceeding browser size
   limits. Use existing code and browser capabilities, not a new waveform/player dependency.
3. Preserve the played-region highlight, source offset, duration trimming, per-asset normalization
   and compact 24 px variant. The library and source-view callers retain the same behavior.
4. Save/Open retains the existing project format. Rebuild waveform data from local media on Open, as
   current peaks are rebuilt. Preserve responsive playback and private local processing.
5. Update the shared Timeline Storybook fixture. Inspect a rendered public or synthetic voice clip
   at fit and maximum zoom against the reference. Keep the existing strict gates and browser
   journeys green. No new test pipeline, 44.1/48 kHz CI fixtures, ffmpeg reference comparison or
   mixed-rate export test is required. A minimal binning unit check is optional, not a gate.
6. Preserve exact-candidate independent review, serialized main delivery and exact-SHA green CI. No
   physical-audio, private-fixture or unmeasured performance claim.

## Boundaries

Likely paths are `src/media.ts`, the `Waveform` hunk in `src/components.tsx`, its timeline props in
`src/Timeline.tsx`, waveform CSS in `src/styles.css` and `src/Timeline.stories.tsx`. Coordinate
UI-8's library-row consumer before any shared-component grant. Preserve timeline scale, ruler and
trim ownership. Keep existing meter peaks or derive an equivalent meter value; do not rename them
merely to force an App edit. REF-30 import progress is related. CLIP-17 gain and CLIP-26 per-speaker
waveforms can build on this data without adding their behavior here.

This brief grants no implementation paths and does not interrupt REF-32 acceptance.
